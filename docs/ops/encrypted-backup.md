## 已验证内容

- 固定官方 age v1.3.2 Windows/Linux amd64 发布包，分别核对官方大小和 SHA-256；只提取所需二进制，没有全局安装。
- 复用第三轮冷恢复的同一份快照，重新核验数据库及全部对象原始字节；不重新捕获线上数据。
- 加密包包含数据库归档、源表内容指纹、可移植对象映射、所有对象字节及应用版本记录，共 1,672 个成员。
  密文为 28,525,560 字节；完整成员清单、长度和 SHA-256 均在加密包内。
- 仅持有公钥的过程可以加密；解密私钥保留在本地集中恢复组，继承仅当前用户、SYSTEM 和管理员的访问权限。
- 解密全过程成功后才解析归档，所有成员与清单完全相等并逐项校验后才向恢复器交付数据。
  错误密钥、末尾/中途截断、正文篡改，以及已加密但内容哈希错误、缺失、额外、重复或越界路径的包均被拒绝。
- 明文归档只在内存中组装和解密；实际 PostgreSQL 恢复时落在独占容器的 tmpfs，未在主机新增明文快照副本。

## 只使用密文的实际恢复

新建独占 PostgreSQL 17/pgvector 与 MinIO，恢复输入仅为密文、本地私钥和已固定的软件镜像；
恢复过程不读取原始快照。数据库写入前确认空 public schema，对象写入前确认空目标。

- 56 张表 / 82,622 行内容指纹与密文内的源快照清单逐项相同。
- 1,668 个对象 / 1,872,148 字节实际写入 MinIO，再逐个读取比较字节，并核对完整对象集合。
- 从开始至两个独占容器清理完成为 17.531 秒；原有运行容器保持。
- 该时间是本地数据库/对象恢复验证耗时，不是整机 RTO；本轮未启动应用，也没有新增供应商请求或线上写入。

此前完整本地 VM 自动恢复与新售前业务结果见[本地冷恢复](local-cold-recovery.md)，两项演练范围分别保留。

## 一致捕获与原生服务验证

- 捕获器使用持久的 `REPEATABLE READ READ ONLY` 事务，实际确认只读状态；表指纹、对象引用和
  `pg_dump` 共用导出快照。隔离源库在捕获期间发生26次更新，恢复后的计数仍为快照时的0，
  源库最终为26；57表/82,623行指纹及1,668对象通过。第二次对象捕获全部命中校验后的内存缓存。
- systemd 服务只安装在已有本地恢复 VM。三个定时快照来自该 VM 已恢复的数据，包含后续本地售前业务：
  56表/82,705行、1,669对象。没有重新捕获生产，也没有复制解密私钥到 VM。
- 原生 botocore 1.34.46 起初不接受 `IfNoneMatch` 参数，三次尝试保留同一密文、零上传。
  兼容实现把相同的 `If-None-Match: *` 条件放入签名前事件，回调在 `finally` 注销；不退化为覆盖写入。
- 实际上传并读回后、记录本地成功回执前，测试进程主动退出17。journald 记录自动重启，
  新进程续传同一快照ID/密文，随后另两次定时备份成功，传输暂存目录为空。
  最终服务停用后的 `NRestarts=0` 不代替真实生命周期证据。首次快照经过人工SDK修复才完成，不能记为RPO通过。
- 最新定时密文实际恢复了56表/82,705行、1,669对象，指纹、逐对象字节和完整集合均相等，
  包含清理共21.047秒；该值仍不是整机RTO。
  原恢复器的全局容器集合断言失败保留：同时运行的 Windows 备份任务清理了它自己的临时容器。
  所属任务、成功回执和清理时间相互吻合，五个常驻容器仍运行；补充核验未把原失败改写为全项通过。

## 容量与留存边界

- 服务在上传前完整列出指定桶的 `operations-recovery/v1/` 前缀，默认上限3 GiB；当前要求该前缀只有一个写入服务。
  把密文及成功标记都计入预算，未知上传和不完整快照同样占用空间；同ID重试只预留缺失对象的字节。
  列表有分页/总键数限制，异常键、重复页或目标不一致均拒绝继续。
- 达到上限时保留待上传密文及最后成功点，返回明确的 `RemoteBudgetExceeded`。
  既有快照的完整读回重试不需要再次预留同一份空间。
- 留存器只产生带精确对象键、ETag、哈希及原因的候选清单，不删除数据。
  至少保留最近五个**已实际恢复验证的不同内容**，另保留固定、引用、失败、进行中、未验证及不完整项。
  较新的未验证上传不能挤掉已验证恢复点。内容身份和恢复证明由可信运维目录提供，不能相信上传标记自称已恢复。
- 真实本地 MinIO 的三份快照/六对象共85,516,410字节：设置上限等于现存大小时，
  原快照重放成功、新ID上传拒绝，六对象及ETag均不变。三份快照全部保留，未生成清理候选。
- 11项新增边界测试和原10项备份测试通过，包括预算失败后的同ID恢复、不同内容保留、
  引用保护、未确认上传、伪恢复声明、分页异常和服务实际调用预算入口。
  尚无生产留存目录、清理批准或自动删除；上传成功与实际恢复始终分开记录。

## 尚待完成的长期备份链路

1. 把源快照年龄、容量不足和未确认上传接入独立监控，完成相应故障/恢复测试；成功上传不能覆盖最近实际恢复时间。
2. 整理生产服务、最小权限目标凭据、可信恢复/引用目录和安装/回退包；服务器只需 age 公钥。
   留存候选在执行清理前仍需获得明确范围的批准。
3. 明确远端敏感备份存放例外后，才安装生产服务及写入指定 R2 前缀；当前实现和测试不构成此项授权。
4. 实测个人电脑离线时服务器仍持续备份，并检查源快照间隔、失败告警与实际恢复。
   原 Windows 队列/备份任务继续保留，不把本地 VM 的成功算作脱离个人电脑。

当前实现将完整包限制在 64 MiB、最多 4,096 个数据成员；超限应失败并保留既有恢复点。
这覆盖本次实际快照，未来增长须先完成流式实现或重新验证明确预算，不能在生产静默放宽。
