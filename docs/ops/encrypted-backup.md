# 加密备份与密文恢复验证

2026-10-02：本地已完成 age 加密、完整解密校验，以及只从密文恢复数据库和对象的实际演练。
服务器定时捕获、远端上传及个人电脑离线时的连续运行尚未实施，因此长期备份门槛仍开放。
脱敏机器记录见[加密备份核验](../../.trellis/tasks/09-24-commercial-operations-acceptance/encrypted-backup-validation.json)。

## 已验证内容

- 固定官方 age v1.3.2 Windows/Linux amd64 发布包，分别核对官方大小和 SHA-256；只提取所需二进制，没有全局安装。
- 复用第三轮冷恢复的同一份快照，重新核验数据库及全部对象原始字节；不重新捕获线上数据。
- 加密包包含数据库归档、源表内容指纹、可移植对象映射、所有对象字节及应用版本记录，共 1,672 个成员。
  密文为 28,525,560 字节；完整成员清单、长度和 SHA-256 均在加密包内。
- 仅持有公钥的过程可以加密；解密私钥保留在本地集中恢复组，继承仅当前用户、SYSTEM 和管理员的访问权限。
- 解密全过程成功后才解析归档，所有成员与清单完全相等并逐项校验后才向恢复器交付数据。
  错误密钥、末尾/中途截断、正文篡改，以及已加密但内容哈希错误、缺失、额外、重复或越界路径的包均被拒绝。
- 明文归档只在内存中组装和解密；实际 PostgreSQL 恢复时落在独占容器的 tmpfs，未在主机新增明文快照副本。

## 只使用密文的实际恢复

新建独占 PostgreSQL 17/pgvector 与 MinIO，恢复输入仅为密文、本地私钥和已固定的软件镜像；
恢复过程不读取原始快照。数据库写入前确认空 public schema，对象写入前确认空目标。

- 56 张表 / 82,622 行内容指纹与密文内的源快照清单逐项相同。
- 1,668 个对象 / 1,872,148 字节实际写入 MinIO，再逐个读取比较字节，并核对完整对象集合。
- 从开始至两个独占容器清理完成为 17.531 秒；原有运行容器保持。
- 该时间是本地数据库/对象恢复验证耗时，不是整机 RTO；本轮未启动应用，也没有新增供应商请求或线上写入。

此前完整本地 VM 自动恢复与新售前业务结果见[本地冷恢复](local-cold-recovery.md)，两项演练范围分别保留。

## 尚待完成的长期备份链路

1. 将一致快照捕获、公钥加密和有界失败处理接到服务器定时服务；验证重叠、重启及失败时保留最后成功点。
2. 实现不可覆盖的密文上传、远端完整读回及成功标记；上传完成与实际解密恢复的状态必须区分。
3. 使用本地隔离目标完成该服务的连续运行与故障测试，再核定具体远端密文路径、对象前缀及最小写入凭据范围。
   敏感备份仍受本地保存规则约束，当前没有上传到服务器或 R2。
4. 最终实测服务器独立运行时的快照源时间间隔、失败告警及恢复点年龄；原 Windows 队列/备份任务继续保留。

当前实现将完整包限制在 64 MiB、最多 4,096 个数据成员；超限应失败并保留既有恢复点。
这覆盖本次实际快照，未来增长须先完成流式实现或重新验证明确预算，不能在生产静默放宽。
