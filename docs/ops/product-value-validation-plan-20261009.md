## 本轮问题与范围

只回答：在相同公开证据、相同当前默认模型下，项目正式生成网关的证据协议，相比简短响应提示，是否改善范围判断、缺口表达和引用可核查性？

在原12条真实历史采购要求中，有意选取3条：SWU01教育授权范围、SWU05客户端JS-API与WebOffice边界、SWU06不同适用条件下的服务时限。它们都有现成公开原文可比，不需要虚构供应商证明。其余9条继续保留为未运行，不是本轮成功分母。样本偏向缺证边界，没有支持、反证、条件满足等完整分布，不推广到总体效果。

两个实验臂：

- **项目生成核心**：在现有staging API容器内调用其未修改的正式 `OpenAICompatiblePresalesGateway`，使用默认auto策略第一路及原提示/契约；不是完整应用业务请求。
- **简短提示基线**：相同路由、模型、reasoning、流式模式、120秒超时和4000输出token上限，依据相同原文回答同一要求，返回答复、缺口和引用。它是直接调用基线，不代表某个商业聊天产品。

公开文本由人工从已保存快照中挑选，两个实验臂收到相同文本与适用说明。输入中的UUID只用于回放关联，不是数据库版本ID。未运行上传、解析、检索、向量、业务队列、故障切换、复核UI或原格式回填，所以不能声称测得整体产品效率或真实用户体验。

## 冻结规则

顺序：SWU01基线→项目，SWU05项目→基线，SWU06基线→项目。每格一次，共最多6个请求；不自动重试、不补抽样、不切换模型。累计两次失败即停止后续，传输结果不确定则停止并核对已有状态，不重发。失败与未执行保留在本轮6格分母中。

执行前只读确认正式模块哈希匹配rc.45应用提交 `d47371b6008afe833e317606b2153285aeafff75`、DB0034、无活动业务任务；默认首路为grok-4.7 / low / streaming / 120秒。没有修改运行配置。

遵守日200调用上限：应用计数之外已有4次直接调用，本轮实际或可能已派发请求继续额外扣除。直接回放不写应用任务/费用账本，因此单独留意图、回执、耗时、usage与供应商请求ID；金额未核实保持未知，不填零。每次请求前重查日期、策略、活动任务和余量。

## 判定与记录

预先冻结的参考另存，模型不接收参考答案。检查每条是否：

1. 区分要求与供应商事实，未无依据承诺“已满足”；
2. 保留产品、版本、授权、时间单位与触发条件；
3. 明确缺少什么材料，并给出具体补证事项；
4. 引用来自本次原文，且能够支持相应文字；
5. 输出可作为人工复核草稿，或明确记录生成/协议失败。

由主助手按冻结参考审读，非独立盲评。单次生成耗时只是技术记录；不估算人的修订分钟数或真实省时比例。需要修改时保留原稿，另存建议稿与修改原因，不能用修订稿回填原模型得分。

比较后的决策：两者同样处理好这3条，仅支持“本轮未观察到额外优势”；项目独有收益需要在其他实际步骤证明。若项目多失败或明显更慢，保留该结果，先检查协议/流程成本是否值得，不马上展开渠道和模型选型。若项目明显减少严重错误，也仅形成后续真实任务验证的线索。
