# Haystack 上下文适配实现与验证

日期：2026-10-11。修改前基线：`913c3f9db68211d4cb7ab47b59279a016f32794b`。
本轮在原有问卷链路中实现可显式选择的 `presales.v26`：复用 Haystack 3.3.0 的窗口检索组件，
保留现有 PostgreSQL、关键词/向量检索、权限、引用、计费、复核及导出。
默认仍为v24；本轮没有发布或部署，也没有新的真实生成、embedding或评审模型调用。

## 1. 实现了哪些边界

- 同步生成和后台任务调用同一个适配层；后台仍按冻结的执行策略恢复。
- 保留v25选出的两条原始可见命中，先为所有来源预留这些位置，再增加邻段。
- 每来源最多3600字符、单段最多1800字符、整次生成最多12个chunk，沿用原有请求字节上限。
- 按距离、原命中顺序、chunk顺序，补充左右最多3段中的完整邻段。放不下或超过1800字符的
  新邻段整段跳过；不截成半段塞入。原命中既有的1800字符前缀规则保持不变。
- 每条邻段继续使用真实chunk ID、版本、原文和偏移。Haystack合并后的窗口文本不进入模型引用。
- 数据库读取重新检查当前用户可见性、租户、版本、active generation与ready状态；
  种子原文/偏移/来源元数据必须与数据库一致。发送模型前再次使用现有权限与任务检查。

例如，两条原命中各1200字符时，可以增加一条1200字符的邻段；两条各1800字符时不会补充。
六个来源各有两条命中时，12个位置已预留完毕，不会为了补第一个来源而挤掉最后一个来源。
`RetrievalNote`继续记录检索数、使用数与截断状态；窗口候选计入新的检索数。

## 2. 复用与版本处理

新增的 `presales/context_window.py` 是项目授权、数据库和预算适配层。
窗口发现与多字段过滤实际调用固定版本 Haystack；没有复制它的算法，也没有重建向量库。
每次只提供已从数据库授权读取的有限chunk，使用只读、请求内存储适配器，
避免引入另一个全局索引或后台执行器。最多读取14条窗口候选，另设溢出保护；SQL文本投影也有界。

v26沿用v25的生成提示词、schema和整题ID；新的版本号绑定的是证据供给策略变化，
不是又一次逐题添加提示词。冻结的v25与v26任务相互恢复会拒绝。
旧v21/v24/v25执行和历史评估保持原规则。离线collector可识别v26，但它仍然只验证生成接口，
不因这个参数变成真实检索实验。

`haystack-ai==3.3.0`加入core依赖及uv.lock。原128个锁定包版本未改变，锁文件新增17个包；
本机环境实际新增16个包，原126个环境包版本未变。差异来自跨平台依赖。
本轮用 `uv sync --locked --inexact` 避免清除原有额外环境包，没有安装torch或重排权重。
适配器在首次延迟导入前关闭Haystack telemetry和auto tracing，组件测试禁止网络。
许可及源码依据沿用[首轮开源核查](./oss-component-reuse-20261011.md)。

## 3. 验证范围

实际组件单测覆盖原命中不变、完整邻段、字符/条目预算、无空间、重复窗口、外域片段、
缺失或伪造种子以及telemetry禁用。真实PostgreSQL覆盖其他来源过滤、失效资料/权限撤销、
伪造ID/文字/偏移、超长邻段跳过、5/6来源的总额度、模型调用前再次撤销，以及同步/后台
引用落库、重放和单次额度结算。两道既有GitLab公开回归验证实际SQL路径下保留v25原命中。

生成响应和向量仍为受控测试边界，没有把这些结果写成真实模型质量提高或独立用户验收。
初次数据库测试有一项测试预期遗漏：撤销资料后，同步服务末尾的GET也应拒绝。
修正测试以符合既有权限契约，未放宽产品权限检查。

最终验证通过：3,322项非集成测试及23项子测试，104项真实PostgreSQL测试（含24项新增窗口用例）；
Ruff格式检查覆盖766个文件，静态检查通过，mypy检查281个源文件无错误。
非集成测试另有851项按标记排除，不计入通过数。
质量门槛、命令、输出与代码哈希收录于恢复组内的
`fallback-model-evidence/oss-context-adapter-20261011-verification.json`。
没有改前端、公共持久化结构或数据库schema，不需要新迁移。

## 4. 已知限制和后续验证

这次解决的是安全、有界地提供邻近证据，尚未证明一般问卷的真实回答准确率提升。
窗口按位置选取，不能识别语义重要性；超长条款会被跳过，额度满时无法补证据。
按来源顺序分配剩余位置具有确定性，但不是跨来源的最优语义分配。
Ragas评审、cross-encoder重排和普通问答/业务条件路径分离仍未在本轮实现。

在后续上线前，需分别冻结真实检索及生成对照，记录关键事实到达、错误义务、漏答、
延迟和成本，并验证目标4核4GB环境的实际容量。本轮没有增加或复用旧的线上调用预算。
第二供应商扩展资料保持未参与调参；真实参与者仍未到位。
