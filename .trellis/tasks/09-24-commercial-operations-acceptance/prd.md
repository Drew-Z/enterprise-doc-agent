# 当前环境业务质量与运维验收

## 前置

依赖商业额度代码与商业发布门槛完成。线上仍按真实已部署版本核验，不直接发布未过语义门槛的 v7。用户明确不配置备用服务器，告警邮箱已在私有运维记录中指定，恢复演练结果由用户核对。

## 可验收任务

- CO-1：精确候选 SHA/镜像/配置记录；GitHub 登录、独立租户、跨企业拒绝、上传解析、引用生成、人工复核和 CSV 完整流程。
- CO-2：冻结来源、gold 与渠道版本，所有调用和失败进入分母；未知不能误判未完成，无支持来源不能断言，人工批准语义质量。
- CO-3：当前 4C4G 下测上传/解析/检索/后台队列/浏览器恢复；故障切换有上限，重复提交不重复收费，不把失败请求成本算零。
- CO-4：外部可用性及队列/备份新鲜度监测；指定接收者收到故障及恢复通知，有值班和处理记录。不得未经授权发信。
- CO-5：先在隔离环境核验当前 DB+对象快照的恢复、交叉引用和文件哈希，不覆盖线上数据。整机故障恢复、独立故障域和 RPO 300 秒/RTO 1800 秒仍为待验收能力；不配置备用服务器不等于已豁免或通过此门槛。
- CO-6：主分支必要检查、禁止强推/删除、发布环境审核；候选版本定点回滚验证，生产发布须有具体变更和批准。

任何外部缺口记录责任和解除条件。当前未通过，不能归档。

## 本地恢复准备的可观察行为

- CO-5a：`local_recovery_drill.run_drill` 接收显式仓库外输出目录；已存在的目录或目标数据库必须在备份/恢复前拒绝，不覆盖历史文件或删除已有库。
- CO-5b：新建隔离目标后，无论恢复成功或失败，都仅清理本轮创建的目标；显式保留模式留下目标和证据供排查。
- CO-5c：备份、库存与报告写入同一私有恢复目录，报告记录绝对本地路径及哈希，维持 `blocked_external`，不伪装成整机故障/对象恢复验收。
- 测试边界：通过 `run_drill` 验证文件和命令行为，仅替代 subprocess；另外用真实本地 PostgreSQL 验证当前迁移与合成账本数据的恢复。原本地 public 与线上数据保持原样。

## CO-5 当前线上数据的本地隔离验证

- 对线上应用 schema 只读备份，引用清单来自该备份的恢复库。集中本地保存文件字节，不向线上对象桶写入快照；明确排除未完成上传和非应用 schema。
- 对象工具拒绝已有输出目录、非法或矛盾的引用以及超过明确对象数/字节预算的输入。下载失败、截断或 SHA 不符不能产生成功清单；错误不得泄露对象名或凭据。
- 恢复只接受本机回环地址和空桶；先校验完整本地清单、字节及其哈希，再写入。已有对象、清单篡改或丢失文件必须拒绝；源对象桶不变。
- PostgreSQL 使用同一导出快照核对 49 张应用表的内容指纹；文件恢复后逐项读回 SHA，并核对恢复库引用。记录完整状态、失败、原始/恢复软件版本和资源清理，不把它称为整机灾备或 RPO/RTO 通过。
- 测试通过对象捕获/恢复的公开函数，替换 S3 传输边界；实测使用当前线上只读源和本机独占临时 PostgreSQL/MinIO，不运行消费者或调用模型。

## CO-3/CO-4/CO-5 恢复后的应用与下一阶段准备

- 使用已捕获且哈希固定的线上 DB/对象快照，重新建立独占本地目标；不重新捕获线上数据。候选迁移仅作用于该副本，必须保留原始快照。
- 用恢复后的数据验证历史响应表读取、草稿导出和跨租户拒绝；新建合成租户验证真实上传、解析、检索、受控生成、复核与导出。实际 JWT 与应用代码执行，模型和向量服务使用明确受控边界，不发送邮件。
- 清理只覆盖本轮独占容器及其内存数据；执行前后固定既有本地容器身份，记录线上调用为零。不能将本地流程与耗时称为 4C4G 生产容量或整机 RTO。
- 当前容量验收配置必须先固定四阶段、两轮、业务覆盖、请求上限、判定指标和实际部署身份的采集方式。审批及外部执行未完成时保持待验收。
- 外部告警准备给出可直接接入的 URL、请求头、响应校验、触发/恢复阈值和收件范围；没有监控账号或发信配置时明确缺口，不制造投递成功记录。

## CO-3 本地业务容量采样切片

- 每个有界任务使用一份哈希固定的合成文件，经真实上传 API、解析队列、Core 检索、后台生成、刷新/同键重放、复核与 CSV；upload / ingestion / retrieval / generation_recovery 分别计时。
- 前序失败、超时、预算耗尽和未执行样本保留在计划分母。预期故障另记断言是否满足，不能算成成功生成；202 接受耗时与最终结果耗时分开。
- 通过本地受控供应商验证主路失败、双路失败、次数上限及逐操作账本的一次结算/释放；不自动重试失败业务，不自动注入远端故障或消耗真实模型预算。
- 复用现有公开应用契约和 Core 检索，原始对象读回 SHA、活动代次/块数、引用绑定、持久草稿和复核必须核验。无需新增产品 API。
- 两轮四阶段、最多 160 任务、并发最多 4、每文件最多 1 MiB；请求数与总时限独立有界。原始材料只存本地显式目录，拒绝覆盖。
- 本切片只放行回环服务和受控环境，报告明确为本地功能/采样结果。采样器实现不等于当前 4C4G、真实供应商、浏览器重连或完整遥测的容量通过。

## CO-3 只读资源观测切片

- 通过已知 SSH 主机的只读 Kubernetes/系统/metrics 入口，固定实际节点、工作负载镜像/资源限制、配置摘要、Pod 身份及重启情况；不读取 Secret，不写远端文件，不新增常驻服务。
- 采样带时间戳、逐源状态和固定数量/总时限。任一目标缺失、过期值、错误或中断保留；不把 NaN、缺失或未更新的计数填零，不以业务进程 RSS 代替整机内存。
- 原始指标仅保留约定名称和低基数标签。指标结果不携带配置明文、网络地址、凭据或供应商错误原文；操作前后核对实际身份，漂移不能通过。
- 为业务阶段关联提供可重用观测文件和离线核验。没有重叠的同环境阶段、足够采样时间或业务执行记录时，只有观测结果，不能成为容量验收。
- 本轮允许当前 4C4G 的低频只读观察，不压测、不调用模型、不发信、不修改部署。测试替代 subprocess/HTTP 边界，再在实际服务器做一次有界观察。

## CO-1/CO-2 前提状态复核切片

- 正确收到的已满足、未满足、待确认状态及逐项证据必须经过生成、保存、读取、人工复核和 CSV 完整保留；待确认不得统一显示为未满足。
- 复核可纠正逐项状态，改变原模型状态需说明依据；不得改写原稿、删除前提或伪造出处，完整保留历次复核。总体判断与逐项状态必须一致。
- 历史未记录结构化前提的草稿明确显示未记录，不能从自由文本推断状态；保留原有复核和导出能力。
- 冻结模型输入、gold、调用/失败及评分文件不变；本切片只修复应用信息丢失，不视为真实模型 unknown/unmet 误判已解决或 CO-2 通过。

## CO-2 逐项语义验收切片

- 将前提状态与“是否允许生产启用”分开判断；缺少完成记录不能推出尚未完成，unknown 的待办应先确认状态，unmet 才要求实际完成。
- 离线逐项评分绑定原始运行、输入、独立的前提参考和人工映射的内容哈希；检查三态、各项证据覆盖、遗漏及多余项。不得按生成文字关键词自动匹配、改判或替换原结果。
- 历史失败、未执行题、未复核项必须留在完整题目分母；新增参考是已知问题的回归补充，不能称为新的盲测。映射和参考由助手编写的结果不得声称独立领域验收。
- 候选提示词、前提参考与有界试验计划先冻结，再开始获准的真实批次。原有 H3 输入/gold、v5/v6/v7 原始结果保持不变；正式发布门槛仍包含正文、分类、引用、独立审核及运营验收。

## CO-3i 指标生产端与新鲜度

- 当前待执行队列从权威 jobs 状态读取，涵盖 pending/retry_wait 且 available_at 已到期的任务；等待时长从最近一次可执行时间起算，空队列的零值必须来自成功查询。运行中、未来重试、终态不计入该值，过期运行租约另属恢复机制，不冒充同一队列指标。
- Redis 使用 INFO clients 的服务端 connected_clients，新指标明确区别旧进程连接数；不枚举客户端身份、队列消息或业务内容。
- 未采集、失败和超时的数值为 NaN/未知；分来源保留最近成功时间与本次成功标记，过期值不能通过观测。失败不得终止业务或填零，两来源独立更新。
- 现有 Worker 负责低频、有界采样并随服务启动/取消退出；API 与 Consumer 不重复扫描数据库。禁用 metrics 时不启动此采样。无新增常驻服务、迁移或公共业务 API。
- 用公开采样/指标/汇总接口验证空闲、积压、消退、断连/恢复、超时、过期和旧版本兼容；真实本机 PostgreSQL 与 Redis 验证查询和连接数，资源独占并清理。远端部署、真实模型、发信仍不在本轮授权范围。
