# 单一引用标识与前提投影 v7

延续用户授权的项目推进。基线 `21b8661e97bfb105ea0d8ad875718709d8250ce1`，复用父任务、PR #8 与集中恢复组的 `presales-single-source-protocol` 阶段。线上 v0.1.44 / presales.v3 不随候选修改。

## 设计与兼容

- 模型输入改为 `SelectionInput`：要求与片段。每段只提供本次 citationId、准确原文、文件名、来源显示标签、版本号/最新版本号、适用范围、页码/标题。来源显示标签用于区分同名文件及同一版本，不是可返回的引用编号。内部 chunk/version/document/generation UUID、hash 和任意额外元数据不外发。所有来源信息取自已授权快照；服务器保留独立的逐次引用目录。
- `SelectionDraft` 不再继承公开 ResponseText；模型不生成 conditions。每项前提只生成一次 condition/state/citations。服务端将所有 unmet/unknown 的 condition 按原顺序去重投影为公开 conditions；met 不入待办。conditional 必须有 outstanding，supported 不得有 outstanding，未知状态不能改成未满足。保留 conflict 澄清、中文、引用与完整输出校验。
- 公开 ModelDraft、历史草稿、复核、CSV、数据库不改。引用无别名、无近似匹配、无错误输出修复，不新增重试或路由。
- 合成 collector 使用 run-v2：每行独立保存实际调用的完整内部 sourceInput，trace.input 仍是实际 wire 输入。评分验证内部输入与冻结资料的确定性绑定，以及模型视图与本次片段的一对一关系；保留旧 run-v1 的原始评分。失败输出不得重解码成成功。

## 行为切片与验证

1. HTTP 边界红/绿：不泄露内部编号或额外元数据，仍能区分同名不同版本与旧版本；原文和来源范围不丢失。未知/UUID/重复/其他请求编号与同版本伪冲突继续拒绝。
2. HTTP 边界红/绿：前提单次生成形成公开待办（met/unmet/unknown混合）；遗漏待办前提、遗留 conditions、错误状态及英语前提拒绝。原条件文本不修补。
3. collector/scorer 红/绿：真实 wire 和内部证据分开保存，来源/范围/片段/引用/结果篡改拒绝，旧报告结果不变，未知用量不补零。
4. 更新受控HTTP模型，跑实际 PostgreSQL 的持久化/复核/CSV/权限/幂等验证；跑售前与 TXT/PDF/DOCX 入库浏览器流程。模型仍模拟，此层不证明语义质量。
5. 全仓非集成、Ruff/format、Mypy，精确提交与最终 HEAD CI。保留全部旧WIP与四个worktree。

## 有界真实模型试验

本地验证后冻结候选完整提示词、代码hash、四份数据与gold。最多24次、每题一次，无重试。顺序 H3 → H4 → H1 → H2，每组6题后评分及逐条语义审阅，任一组出现无有效草稿、错误分类、缺必要证据、错误事实/前提状态或无效澄清则停止后续组。H4此前未调用，其余都是已知回归；全部为助手编写自审，非独立专家盲评。

120秒总请求时限、max_tokens=4000沿用现配置（非供应商账单硬上限）；最多24次/48分钟请求等待。不修改线上路由/认证/客户资料/额度、不发邮件、不增常驻服务。失败不能通过降低门槛、改gold、重试变成功。结构改动不保证 unknown 语义自动修复。所有24题首次分类/证据/语义通过才具备进入既有发布与公网演示验收的条件；否则保留候选并报告确切剩余问题。

## 失败复盘

根因类别：接口冗余及可选标识歧义。v6靠提示词同时约束多个UUID与重复条件，仍出现错选和逐字不一致；这是适合消除的接口负担。输入投影和输出单一来源是预先定义的契约，不处理历史失败结果。语义错误、网络问题、模型质量另行保留并核验。
