# 答案审阅指南

本指南面向没有参与开发的独立审阅者。操作参与者先完成任务并提交结果，审阅者随后才接触 `reference/`；观察者不能在运行前或运行中透露答案草稿。

1. 核对候选报告、pack manifest、原 `reference.json` 和全部 `upload/` 哈希与评测计划一致。
2. 按对象 × 字段逐项读取冻结原文，先形成自己的判断，再查看 `review-notes.json`。
3. 对每行记录 `agree`、`revise` 或 `reject`，并记录审阅者、UTC 时间、理由及最终引用。发现软 404、动态内容缺失或归属不清时保留缺口。
4. 严重错误至少包括跨对象串源、把缺失写成确定值、错配套餐/商品版本、丢失关键退款/税费/地区条件，以及把共同需求当事实证据。
5. 同义改写可判事实等价；必须同时比较 `action`、证据状态、值、条件、引用归属和是否保留未知项。原评分器的精确字符串比较不能替代这一步。
6. 先完成全部 30 行独立复核，再由另一人抽查争议项和所有严重错误判定。未完成时 `independently_reviewed` 必须保持 `false`，`quality_score` 必须保持 `null`。
7. 正式 reference 应写到新文件并更新新评测计划的哈希；不得悄悄覆盖已经冻结并绑定的候选 reference。

本轮助手草稿不算独立客户 UAT，也不能替代真实使用者反馈。
