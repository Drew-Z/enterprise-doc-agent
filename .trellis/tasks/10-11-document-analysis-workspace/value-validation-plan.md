# 首轮真实任务验证

用户已批准按本计划执行。当前目标是验证文档比较任务的实用性；独立试用暂无参与者。

## 冻结范围

- 单任务最多 3 个比较对象、10 个字段；多文档取证、引用与缺口、人工复核和 XLSX 导出。
- 首包使用 `materials/validation-01` 的 7 份上传材料；参考答案与助手审阅底稿不上传、不进入提示词。
- 固定流程和有限 Agent 共用一个已冻结快照、`analysis-primary` 路线与 `gpt-5.6-sol`，禁止静默换模型。
- 两臂各 30 个单元，每单元最多 2 次派发，合计最坏 120 次；运行前检查共享每日 200 次上限、provider 更严格的上限和租户权益余量。不通过缩小统计分母掩盖失败。
- 本轮不增加新框架、OCR、多 Agent 或行业推荐能力。

## 执行顺序及产物

1. **可运行候选**：发布已验收源码的签名不可变镜像，分别检查候选自身和现有 rc.51 在候选迁移后的 0044 隔离空库上启动。记录精确 digest、schema、探针和清理结果。空库 smoke 不代表已有分析历史接管。
2. **受控环境**：复用既有 4C4G 主机与发布链，先应用默认关闭配置及迁移；核验短期令牌、真实路由、调用余额，再为受控租户开启。部署证据与模型执行证据分别保存。
3. **首包对照**：通过产品上传、项目、快照和 run API 执行 fixed/agent；由 `evaluate_analysis_holdout.py` 从真实账本导出状态、调用量、token、费用和时间。未知成本保持 null。保留完整 60 行分母，包括未运行和失败行。
4. **逐行诊断**：按事实错误、引用不支持、遗漏、冲突未保留、格式失败、超时、工具无效分类；记录需要修改的单元及修改前后内容。助手复核只标为内部诊断。没有真实人工操作时，不填写人工耗时或独立评分。
5. **修复后复验**：只针对主要错误修改，保留首轮结果；使用 `holdout-football-01` 检查迁移效果，不用同一包反复刷分。首包一旦用于调试，就不得继续称为未见留出。
6. **容量与试用**：任务质量可接受后再执行既有 4C4G 计划。试用包可先备齐；独立 UAT 等真实参与者执行后才关闭。

## 停止与验收

路线身份不符、额度不足、未决/超时派发或结果边界不清时停止后续模型派发并保存已发生的账本。保留既有评分器的独立参考门禁，不为内部诊断改低门槛。

本轮完成标准依次为：签名候选可追溯、0044 运行兼容通过、受控环境可用、两臂真实结果完整、内部问题清单和修改量可复查。正式质量结论、人工节时、付费意愿和独立 UAT 均需对应真实证据。
