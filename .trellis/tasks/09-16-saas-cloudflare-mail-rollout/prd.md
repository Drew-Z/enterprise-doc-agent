# Cloudflare 私有邮箱公网基础接入

## 目标

把已提交并验收的私有邮箱包接到选定 Cloudflare 账号，提供有私有凭据保护的 HTTPS 网页/API，为后续收信规则及 Keycloak 身份邮件接入提供真实基础设施。

## 已知条件

- 用户已委托选择域名、地区和统一身份服务，并在上一交付提交后要求继续推进。沿用 ciallobill.ccwu.cc 和 Keycloak；本轮直接推进可逆的独立测试资源接入。
- 不变输入是 Git eca462385da540fef163e80d90e82e55383f05d4 中的私有邮箱包，包内 manifest SHA-256 为 48ce026cc9360c5644b8b36c4c42fa6b5f72648e39daf96e7d8c176b5cb63f21，已有 29 项真实本地验收。
- 实时预检中，选定 zone active/full，DNS 为空；账号只有三个既有 D1、一个其他 Worker。Token 可用，直接 Email Sending 子域接口仍返回 401。
- 当前官方指南在控制台添加 Email Routing 子域；DNS API 的 subdomain 查询参数已弃用。收信子域尚未开通。
- 试用团队仍为零；本轮只处理合成测试账号，不能据此声称客户验证或商业可用。

## 要求

- R1 验证固定包和每个部署文件，拒绝改动、额外文件、链接及不匹配的输入，不重新构建或改写旧交付。
- R2 在任何云端写入前核验账号/zone、D1 名称、Worker 名称、网页 DNS 和 custom domain 的冲突；冲突或读取失败时停止。
- R3 只创建新的 docagent-private-mail D1。选择 apac primary location hint，关闭 read replication；这不是新加坡或任何单一地区的驻留承诺。
- R4 配置独立站点、管理员、签名密钥，通过 Cloudflare secret bindings 注入；本机文件使用受保护 Windows DACL。日志、计划和报告不得包含密钥、Address JWT 或真实邮件。
- R5 在 inbox.ciallobill.ccwu.cc 提供私有站点，关闭 workers.dev/preview、发信、自动转发、公开建址、持久日志和定时任务。先完成无密钥时关闭的上传，再关闭备用入口、注入密钥，最后连接网页域名。
- R6 验证实际 HTTPS、认证失败/成功、管理员建立两个合成邮箱、空收件箱和零 sendbox；分别记录 API、浏览器、DNS/收信的真实边界。
- R7 保留每步云端写入的脱敏结果和不确定状态；不自动重试创建/写入或自动删除资源。现有工作区改动必须保留。

## 验收

- [x] AC1 固定输入核验和拒绝篡改通过，旧包字节不变。（R1）
- [x] AC2 冲突、API 失败和异常响应测试证明不会继续云端写入。（R2、R7）

- [x] AC4 密钥文件 DACL 和公网 Worker 配置实测符合私有默认值。（R4、R5）
- [x] AC5 HTTPS/API/浏览器检查通过，并明确区分网页可用与邮件接收尚未接通。（R6）
- [x] AC6 保存资源清单、恢复边界、后续控制台步骤、差异及清理结果。（R7）

## 本轮边界

本轮不发送真实邮件、不将账号已验证收件人自动作为试发名单、不启用 Sending 或付费套餐、不托管长期 Keycloak、不宣称完整 SaaS 旅程完成。收信子域需按官方支持入口配置后才能独立验收；在它完成前没有公网邮件投递通过结论。正文保留期限尚未实施，不允许真实客户资料/身份链接进入此测试环境。
